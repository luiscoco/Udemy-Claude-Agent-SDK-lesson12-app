01

Keep a session alive

Use an async user-message generator. Hold the second prompt on a promise until the first result and the student’s Continue action. Streaming an HTTP response alone is not SDK streaming input.

02

Switch models between turns

Call setModel on the existing Query object. Inspect the actual assistant model field for both turns and compare the returned session IDs.

03

Change permission mode deliberately

Start the classroom edit in plan mode. Review its proposal, then use the Continue button to call setPermissionMode("acceptEdits") before the scoped status.txt edit.

04

Apply runtime settings

Call applyFlagSettings with settings-file keys such as effortLevel, not the query option name effort. Observe actual hook metadata before and after the change.

05

Persist settings with clear scope

Call updateSettings for local outputStyle and the user default effort. These writes stay inside this app’s private project and SDK home. The saved user effort does not change the running session’s effort.

06

Verify later-session behavior

After writing settings, launch a separate verification query without an effort override. Compare its actual output style and hook effort with the running session’s evidence. Keep model-switch cache costs in mind.
