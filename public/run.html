01

Check prerequisites

Use Node.js 24+, npm and an Anthropic key with access to pinned Sonnet 4.6 and Opus 4.6 for the model-switch experiment. Keep optional dependencies enabled. Python is not needed to run this TypeScript app.

02

Install, configure and start

From presentations run the commands below. Preserve an existing .env; otherwise copy the safe template. Enter your key locally and keep the terminal running. Shell variables take precedence over the optional file. The classroom model IDs are explicit constants in src/agent.ts.

cd .\agent-sdk\lesson12-mid-session
npm ci
if (!(Test-Path .env)) { Copy-Item .env.example .env }
notepad .env
npm start
# http://127.0.0.1:3112
ANTHROPIC_API_KEY=your_api_key
PORT=3112
03

Switch the model between two turns

Start the default model-switch experiment. Wait for Paused after turn 1. Review the first answer and actual Sonnet model. Click Apply changes and continue. Inspect acknowledged setModel/setPermissionMode calls, actual Opus on turn 2 and the same live session ID.

04

Review a plan, then approve one edit

Select the plan-to-act experiment and Start. Review the draft → reviewed proposal and plan-mode hook evidence. The file has not been approved for editing yet. Click Apply changes and continue. Verify acceptEdits, the actual guarded Edit and status.txt changing on disk.

05

Apply a runtime effort setting

Choose runtime effort, Start, wait for the first result, then Continue. Inspect applyFlagSettings({ effortLevel: "medium" }) being acknowledged. Compare actual hook effort: low on turn 1, medium on turn 2. Do not infer hidden reasoning or guaranteed latency from the setting.

06

Persist private settings and verify later behavior

Choose persisted settings, Start, wait and Continue. The real SDK writer saves local Explanatory style and user medium effort inside private classroom paths. Inspect file projections, live turn 2 still using low effort, and the separate new query loading Explanatory/medium without an effort option override.

07

Read results and lifecycle in the correct scope

The two live results share a session ID. The persisted-settings verification query has its own ID. Read latest cumulative cost for each query; do not sum turn totals. Stay on the lab page while paused. Navigating away closes the response and aborts the run; restart if it times out.

08

Use the CLI and troubleshoot

CLI samples automatically continue after the first result and label that automation. The web application waits for its button. Run samples sequentially. If Windows requests Git Bash, set its verified path. A second server start recognizes this app; use a different PORT for an unrelated listener. Ctrl+C stops it. Rejected methods or provider failures remain failures; no saved result substitutes for them.

npm run sample:env -- switch
npm run sample:env -- plan-act
npm run sample:env -- runtime
npm run sample:env -- persist
npm test
