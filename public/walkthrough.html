01

Query controls

TypeScript methods live on the Query object. Python uses ClaudeSDKClient for setters; Python query returns an iterator. This app executes TypeScript only.

02

setModel default

Passing no model clears the override and selects Claude Code’s default, not necessarily the model originally passed. That variation is reference only here; the live switch uses two explicit pinned IDs.

03

Permission changes

acceptEdits changes edit oversight, but application guards and organization policy still apply. This app does not use bypassPermissions or grant access to arbitrary files.

04

Runtime versus file settings

applyFlagSettings uses settings-file keys and affects the session. updateSettings allows only supported targets/keys. This app enables private user/local sources for its settings-writing scenario.

05

Persisted user effort

The saved default belongs to the current model and does not change its running effort. Actual low effort on live turn 2 and medium in the new query demonstrate that distinction.

06

Cache and cwd trade-offs

Switching models can require the conversation to be processed uncached at the new model’s rates. Switch at meaningful phase boundaries. No cwd setter exists; start a new query for another directory. This app does not benchmark cache behavior.
